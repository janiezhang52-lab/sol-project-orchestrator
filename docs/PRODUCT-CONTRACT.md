# Sol 不可变产品合同 v1

简体中文 | [English](PRODUCT-CONTRACT.en.md)

状态：`FROZEN_PRODUCT_CONTRACT_V1`

本合同来自已通过 Windows 与 macOS 产品验收的 V9 四角色链，以及已通过双平台完整链的 Sol MVP 0.3。Git 兼容只能扩展实现边界，不得改变本合同。

本文件是产品应满足的公开规范，不把实现结果、独立验收、技术收口或用户产品决定混写为同一事实。v0.3.3 的公开验证身份与证据边界见 `provenance/PUBLIC_PROVENANCE.md`。

## 产品承诺

用户只与 `00｜Sol 项目总控` 交互。Sol 在同一保存项目中编排三个不同的可见角色任务：

1. `01｜任务执行`：只负责执行冻结目标，不能自我验收。
2. `02｜独立验收`：独立、只读核验目标与真实产物，不能代替技术收口。
3. `03｜技术收口`：核对执行与验收是否属于同一目标、证据是否完整、阻断是否诚实，决定能否进入用户产品决定门。

固定主链：

`立项 → 四个同项目可见任务就绪 → 去执行 → 任务执行 → 独立验收 → 技术收口 → 用户产品决定`

## 不变量

- 四个可见任务分别是总控、任务执行、独立验收、技术收口；不得删除、合并或由隐藏代理替代。
- `execution=COMPLETE`、`acceptance=PASS`、`closeout=TECHNICALLY_CLOSED` 是三个不同事实。
- `TECHNICALLY_CLOSED` 不等于 `PRODUCT_ACCEPTED`。
- 只有用户在总控任务中的明确产品决定才能产生 `PRODUCT_ACCEPTED`。
- 项目绑定必须使用非空真实 `projectId`、精确项目根、`hostId` 与当前总控任务身份；仅 cwd 相同不算绑定。
- 冻结目标在 `去执行` 前不得触发产品写入。
- 编排进度只来自一份本地权威账本；请求、聊天文本与 Agent 记忆不得成为第二状态源。
- Host mutation 必须先有账本 intent；结果未知时只允许核对或停止，禁止盲目重发。
- Agent 只执行 driver 给出的唯一动作并回填原始 Host observation，不自行选择下一阶段。
- 技术失败、需要修订、拒绝产品和接受产品必须保持不同终态；不得自动开启下一轮修订。

## Git 兼容边界

- Sol 控制状态不得写入用户项目树。
- Sol 与三个角色不得执行 Git 命令或直接修改 `.git/**`。
- 正常 Git 兼容的产品门是：工作区只出现冻结目标允许的产品差异，不出现 Sol 控制文件。
- Codex Host 自有 checkpoint 行为由外部黑盒 harness 单列观察；不得把 checkpoint 路径、对象取证或 actor 归因规则塞进运行时 Skill 或角色提示词。
- 若用户要求整个 Host 的 `.git/**` 字节绝对不变，应诚实报告当前 Codex saved-project 环境无法保证，而不是改写目标。

## 变更规则

角色数量、角色职责、固定主链、用户产品决定权或上述 Git 承诺的任何变化，均属于 `PRODUCT` 变更。没有用户逐项明确批准，开发必须停止。
